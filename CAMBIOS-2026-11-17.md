# Artimañas 2026 — optimización y hero

## Usar esta entrega

- `Artimanas-2026-proyecto.zip`: proyecto editable completo, con el bundle del shader ya compilado. No incluye dependencias instaladas, historial Git, perfiles de navegador, capturas ni `dist` duplicado.
- `Artimanas-2026-publicar.zip`: archivos estáticos completos para publicar. Descomprimir y subir el contenido completo a Netlify. No subir el ZIP como archivo suelto.

Para probar el proyecto editable, descomprimirlo y ejecutar desde esa carpeta:

```sh
npm run dev
```

Abrir http://localhost:8080. Este comando usa solo Node.js; no requiere instalar dependencias. Live Server también sirve. Abrir mediante HTTP, porque el shader carga un HDR.

Para generar `dist/` usando el bundle incluido:

```sh
npm run build:static
```

Si modifican `Hero.jsx`, las paletas o `src/hero-*.jsx`, recompilar el shader:

```sh
npm ci --legacy-peer-deps
npm run build
```

## Incorporar sobre la carpeta que ya usan

Copiar el contenido del proyecto editable sobre la carpeta actual respetando las rutas. El ZIP no contiene `.git`, por lo que conserva el historial local al copiarlo sobre el repositorio existente. Revisar el diff y crear un commit de esta actualización.

Las imágenes originales reemplazadas se enumeran en `scripts/optimized-assets.json`. Se pueden archivar fuera del proyecto. Si quedan en la carpeta antigua, `build:static` y el build completo las excluyen de la publicación para evitar duplicación.

Para recuperar espacio de las pruebas anteriores, cerrar los navegadores de prueba y retirar `.pages-preview/` de la carpeta anterior. Era una carpeta generada de unos 508 MiB con perfiles de Brave y copias del sitio. Conservar fuera del proyecto cualquier evidencia que quieran guardar. `node_modules/` sigue siendo necesario para recompilar el shader y ejecutar las pruebas de navegador. `.git/` conserva el historial y no forma parte de esa limpieza.

## Qué cambia

- Nueve imágenes optimizadas. Logo, tickets y fondo de error usan WebP sin pérdida, con dimensiones y píxeles RGBA conservados. Fotos en WebP calidad 88 y lado máximo de 2400 px. Favicon PNG corregido a 64×64.
- ShaderGradient carga únicamente `city.hdr`; conserva el mismo archivo, cámara, resolución y cinco paletas. La adaptación está aislada y el build exige la versión 2.4.20 fijada en el proyecto. Una actualización de esa librería requiere revisar esta integración.
- El ticket y la imagen de error usan carga diferida.
- Seis contornos reconstruidos a partir de la referencia de 2048 × 1280: curvas individuales para las piezas laterales y superiores, en lugar de repetir una forma genérica. No se carga ninguna imagen de burbuja.
- Movimiento autónomo leve, deformación continua y reflejos calculados desde las normales de la superficie. Un render target captura el gradiente actual para refractarlo dentro de cada burbuja.
- Presión local por proximidad del mouse, sin pulsar botones. Cada punto del borde cede y vuelve con un resorte amortiguado; los reflejos siguen la superficie deformada. Se eliminaron la captura del puntero, el arrastre y el cursor de agarrar. Movimiento reducido conserva presión directa sin animación autónoma ni rebote; el scroll táctil no se intercepta.
- Conserva las cinco paletas del gradiente, el grano y el desenfoque del primer nombre (aproximadamente 1,86 px iniciales; siguientes 3,2 px).
- El grano usa una textura PNG repetida de 192×192, sin reactivar el pase de postprocesamiento del shader. Intensidad en `css/hero-effects.css`.
- Hero de escritorio de 90dvh. Se adelanta el primer nombre con blur leve; los siguientes aparecen más desenfocados y con menor opacidad. La nitidez se recupera al entrar al catálogo. El título de la lista conserva nitidez.
- Se reutilizan el bloqueo de clic en portada y el recorrido existente que centra la primera obra. No se altera la navegación ni los datos de las 32 obras.
- Las medidas existentes del logo apilado y la portada de tablet/móvil se conservan. En esos tamaños se simplifica la decoración; la columna de alumnos continúa oculta como en la versión recibida.

## Peso y comprobaciones

Publicación anterior: 43.987.616 bytes (41,95 MiB). La publicación nueva ocupa aproximadamente 15 MiB, incluyendo el nuevo glass y el grano: una reducción aproximada del 64%. El ZIP editable también evita incluir los 508 MiB de archivos temporales. Esto no significa que una visita descargara toda la carpeta de desarrollo.

Comprobado en este entorno:

- Compilación de producción completa.
- `npm run test:optimized`: recursos locales, 32 obras, favicon de 64×64, ausencia de originales redundantes en `dist`, un solo HDR en el bundle y presupuesto de publicación menor a 17 MiB.
- Prueba de comportamiento del glass: asentamiento sin bucle continuo, pausa fuera de pantalla, entrada táctil y movimiento reducido.
- Compresión sin pérdida del logo, los tickets y el fondo de error comparada píxel por píxel; fotos recompuestas con compresión con pérdida.
- Sintaxis de los scripts nuevos y modificados.
- Inspección de la ilustración SVG y de una composición estática; no equivale a una captura real del navegador.

La prueba integrada de navegador no pudo ejecutarse: Chromium está bloqueado al crear su socket de perfil en este entorno. No se presentan FPS, métricas de carga ni comprobaciones visuales responsive como mediciones realizadas. La suite de navegador queda disponible para ejecutar localmente.

Después de instalar las dependencias y Chromium de Playwright, o de configurar `CHROMIUM_PATH` con el navegador local:

```sh
npm run test:optimized
npm run test:hero-effects
npm run test:publication
npm test
```

Revisión manual: recorrer el hero con el mouse; comprobar el grano sobre zonas claras/oscuras; iniciar el scroll y verificar el primer nombre y el centrado de la primera obra; abrir/cerrar ficha, filtros y ticket; repetir a 1440, 768 y 390 px. Comparar las fotos optimizadas en el detalle antes de publicar.

## Entrega procedural

Cambian `src/hero-shader.jsx`, `index.html`, `css/hero-effects.css`, `scripts/optimized-assets.json` y el bundle compilado `js/hero-shader.bundle.js`. Se agregan `src/hero-glass.jsx` (integración y puntero), `src/glass-shader.js` (superficie y luz) y `src/glass-motion.mjs` (disposición y movimiento). Se actualizan las pruebas. `js/hero-glass.js`, `assets/hero-glass.svg` y `assets/hero-glass.webp` quedan fuera de la publicación y ya no se referencian.

No hay nuevas dependencias ni un segundo canvas. El efecto agrega un pase de composición y un render target a la resolución reducida del canvas existente. Por eso requiere más GPU que superponer una imagen, aunque elimina aproximadamente 190 KB de esa textura. No se midieron FPS en dispositivos reales.

Es una simulación visual de cristal en espacio de pantalla, no una simulación volumétrica de fluidos: las burbujas no colisionan ni se fusionan y no refractan el logo HTML. Sí refractan el gradiente animado que tienen detrás.

### Comprobaciones

- `npm run build`: correcto.
- `npm run test:optimized`: recursos, 32 obras, ausencia de texturas antiguas y presupuesto de tamaño correctos; pruebas de presión por proximidad, recuperación, movimiento autónomo y movimiento reducido correctas; integración de pointermove con los uniforms del render comprobada en un entorno simulado.
- Fragment shader compilado y renderizado con OpenGL ES 3 / EGL sobre un gradiente sintético. Esto comprueba el shader aislado, no reemplaza la integración en navegador.
- Chromium no pudo iniciarse por restricciones de sockets del entorno. Queda pendiente `CHROMIUM_PATH=/ruta/a/chromium npm run test:hero-effects` y la revisión visual del sitio en desktop/móvil.

### Cómo probar

Ejecutar `npm run dev` y abrir la dirección indicada. Verificar que las siluetas cambian lentamente sin mover el mouse; acercar el mouse a un borde sin hacer clic y observar la hendidura local, luego alejarlo y observar la recuperación. Bajar al catálogo y verificar que el primer nombre recupera nitidez. Volver arriba y comprobar que la animación se retoma sin saltos. Probar también movimiento reducido y scroll táctil.

Para cambiar el tamaño y distribución: `GLASS_CONTOURS` en `src/glass-motion.mjs`. Para cambiar el acabado: `src/glass-shader.js`. Los cambios de esos archivos requieren `npm run build`; `build:static` solo empaqueta el bundle ya compilado.

## Corrección de presión por proximidad (v4)

Se modificaron `src/hero-glass.jsx`, `src/glass-motion.mjs`, `src/glass-shader.js`, `css/hero-effects.css`, `index.html` y el bundle `js/hero-shader.bundle.js`, además de pruebas y documentación. El HTML usa `pressure-4` en la URL del bundle para evitar reutilizar la versión anterior en caché.

El contorno se interpola con curvas cuadráticas y sus normales se calculan sobre la curva. Son 32 puntos por pieza, con descarte por límites antes de evaluar cada pieza. Se verificó el shader aislado en reposo y bajo presión con EGL/OpenGL ES. No se ha medido rendimiento real en teléfonos ni se ha completado la revisión visual del sitio en navegador.

La forma sigue la referencia mediante trazado manual e interpolación; no es una reproducción píxel por píxel. La presión es una deformación visual elástica, no una simulación de gas.
